# 最新 main 集成与生产发布计划

用户已授权：推送迁移分支、提 PR、合入 main、处理其他 PR、清理远程分支并更新生产。无需重复请求这些步骤的审批。

## 要求

- 保留 main 新增的 Flash/Ruffle、上传及 B 站解析功能，继续使用指定新栈。
- 合并既有部署 PR 的容器化意图；生产目前由 localhost-1 的 PM2 提供，宿主机 PostgreSQL/Redis 与 Cloudflare Tunnel 需先核实，不影响共享服务。
- 生产备份与真实副本演练先于切换；保留旧应用、数据库、上传和明确回退入口。
- 本机只改代码和 Git；所有安装、构建、集成、浏览器与容器在指定构建机完成；所有下载使用既有代理。

## 并行实现

1. 数据结构：适配存在或不存在 `Video.contentType` / `ContentType` 的旧库，保留现有字段与全部数据，补齐真实数据库回归。
2. 页面：将 main 的 Flash/Ruffle 上传、播放、角标适配 RR8，保留新 Video.js 引擎和 oRPC。
3. 接口：将 main 的 B 站播放解析、同源 `/api/bili/:vid` 及 contentType 业务能力适配 Hono/oRPC。
4. 主代理：解决运行工具与文档冲突，集成部署 PR，统一审阅、远程验证、PR 合并与发布。

## 发布顺序

1. 推送并创建迁移 PR；合入最新 main，逐项审阅新增功能，处理既有部署 PR。
2. 完成最终远程检查和浏览器回归；查看 GitHub 新鲜状态与评论，合并 PR。
3. 更新 main，确认远程分支已无独有未保留工作后清理。
4. 备份生产，真实副本演练迁移、验证记录和上传；构建 final main 镜像。
5. 在有回退准备的维护窗口切换，验证健康、外网真实页面、数据计数和关键流程，记录最终版本。
