## 弹幕保存安全修复与已通过回归

只读审阅发现旧弹幕保存逻辑直接使用请求 `videoId` 拼文件路径，缺少保存鉴权并写死 `cwd/uploads`。主验证流程已明确授权修复。

当前实现将公开读取与受保护保存分开：保存重新读取有效会话、封禁、最新角色与 `video:manage` scope，要求视频归当前用户或属于获准管理范围。批量请求先校验全部输入和全部视频权限，全部通过前不访问 B 站、不建目录、不写文件。来源仅接受规范 CID / BV 标识，不能提交任意远程 URL。

文件保存使用 `UPLOAD_DIR` 的真实目录，业务 ID 摘要生成文件名；拒绝上传根外的目录符号链接，以随机临时文件原子替换目标，避免跟随既有文件符号链接。保存后更新视频 `danmakuUrl` 并失效缓存。

新增安全回归检查匿名、非所有者、缺 scope、封禁后会话、跨站请求、路径穿越、无效来源、缺失视频、整批预检、`UPLOAD_DIR`、文件 / 目录符号链接边界。拒绝场景通过 `fetch` spy 禁止外网；实际写入使用合成视频与临时目录。测试现在要求 `TEST_DATABASE_URL` 明确指向专用测试库并与应用连接一致。

**状态：新增安全回归已在专用构建机真实通过，计入最新 HTTP 14/14、74 个断言。拒绝场景没有访问 B 站，写入边界使用临时目录和合成记录。**
